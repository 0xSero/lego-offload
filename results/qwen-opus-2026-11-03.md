## Code changes made for this trial (uncommitted)

- `route.py`, `transport.py`: `$ANTHROPIC_API_KEY` as an alternative to the Claude Code OAuth login. The OAuth beta header and the "You are Claude Code" system opener go out only with the OAuth login: **with an API key, Anthropic refuses any request carrying that opener ("credit balance is too low"), whatever the balance.** This made every omp-to-cloud job fail silently in the first suite run (0 bytes reached the cloud, so the leak table was vacuously clean).
- `transport.py` (node runner): the local model now sees the `returns` schema in its system prompt, as the cloud path already did. Without it Qwen reasoned to the right answer (Executive, 310) and then filled the constrained JSON with the example values from the task text (Research, 143).
- `transport.py` (`find_ids`): never greedy. At temperature 0 Qwen looped for 261,287 tokens on one CSV (34 minutes, `finish_reason: length`, no identifiers): a four-sentence cycle over the manager column ("Need maybe include X as manager in ... If unique, once."). Re-run on 2026-11-03 with a 32k cap, same CSV, same prompt (`~/lego-demo/traces/`): at the model's default temperature 1.0 it finished in 6,589 tokens (107 s, 40 identifiers, 379 of 408 reasoning sentences distinct); at 0.6 it finished in 12,705 tokens (178 s, same 40 identifiers, 807 of 927 distinct), so the earlier 0.6 run that hit the 12,000 cap was rambling, not looping. `find_ids` now sends no temperature (the model's defaults apply) and a 32,768-token cap unless the policy's `request` says otherwise.
- `door.py`: a model's `request` dict (sampling fields) passes through the policy into every request to that model.
- `vm.py`: starts a user-local `container` install with `--install-root`.
- `tests/e2e.py`, `tests/leaks.py`: the cloud model comes from your policy (first model with `api`), default Sonnet; `request` passes through too. `tests/vmcheck.py`: the route check accepts a success body, not only an error's `request_id`.
- README and the lego skill mention `ANTHROPIC_API_KEY`.

## Project 1: a normal task (`~/lego-demo`)

Prompt to `lego claude -p` (Opus): add a `summary` command (average salary per department) with a test, then say which department has the highest average in the real HR export.

- Opus wrote `payroll/cli.py:summary`, the test, ran both tests in the VM (pytest absent, called the functions), then offloaded the private question to Qwen with `returns` = tuple(enum of 14 guessed department names, int 0..1000 in thousands), 14 bits of the 16 for hr.
- First run (before the fixes): 38 min, answer `["Research", 143]` (wrong, see above), 486 KB to the cloud, **0 canaries** in any byte that reached Opus. Files: `~/lego-demo/reply-normal.md`, `~/lego-demo/route-normal.jsonl`.
- Probe after the fixes (`door.offload` directly): vault scan 162 s, answer `["Executive", 310]` (correct) in 321 tokens at the 120 s deadline; a second ask became a receipt (2 bits left).

## Audits (framing: "this code is bad and probably full of flaws")

- **Fable**: `audit/fable-2026-11-02.md`. 4 confirmed, 2 plausible. No undisclosed byte leak below level, no allowance bypass, no undisclosed timing channel. One genuine gap: layered encodings (base64 of base64, base64 of percent-encoding) slip past `scrub.decoded()`'s single-pass `Unscrubbable` refusal, contradicting the README's "refused" claim for machine-encoded identifiers. The rest restates disclosed limits (scrubbed keeps numbers, dates, sentences; lowercase everyday-word surnames in the omp relay) and notes the Lean proof assumes the scrubber boundary.
